# Access and case evidence

## Investigator sign-in

Use your own user identity and the customer's already approved **Exchange Online PowerShell** access. Use a supported PowerShell and ExchangeOnlineManagement version pair from the [platform setup](prerequisites.md#windows). In `Connect-ExchangeOnline -UserPrincipalName $YourCustomerSignIn`, set `$YourCustomerSignIn` to your own approved sign-in address. Microsoft handles authentication and MFA outside BEC. If the native client is blocked, prompts for new consent, or lacks a role, stop or use existing exports. BEC needs no registered application, client ID, application secret or token. [Microsoft connection guide](https://learn.microsoft.com/en-us/powershell/exchange/connect-to-exchange-online-powershell?view=exchange-ps)

The adapter requires exactly one active, unprefixed, direct interactive Exchange user session. It verifies the tenant GUID, account and connection ID, and uses only that connection's exported cmdlets. Use the optional `-TenantId` to pin a GUID obtained independently from the incident record. It must match the session's tenant GUID. BEC displays the operator and tenant GUID without inferring a customer label from an email domain. Review the accounts, UTC window and retained range, then enter **yes**. Confirmation defaults to no, and **q** cancels. BEC never signs in automatically.

The adapter checks the exact primary SMTP address with `Get-Mailbox` before incident reads and stops if the session changes. An unverifiable mailbox or session stops collection. `-DelegatedOrganization` is a Microsoft CSP facility for existing customer delegation. This adapter declines those sessions, app-only sessions, Security & Compliance sessions and ambiguous connections. A guest's sign-in suffix cannot establish the customer. Windows script-policy acceptance and live tenant operation remain unverified. [Session metadata](https://learn.microsoft.com/en-us/powershell/module/exchangepowershell/get-connectioninformation?view=exchange-ps) · [Microsoft connection guide](https://learn.microsoft.com/en-us/powershell/exchange/connect-to-exchange-online-powershell?view=exchange-ps)

## Microsoft sources and limits

| Source | What BEC reads and reports |
| --- | --- |
| Exchange message trace | `Get-MessageTraceV2` reads by sender and recipient for the exact account, in ranges of at most ten days within rolling 90-day retention. BEC requests up to 1,000 rows per direction per range and flags a full result. Capped, denied, throttled, empty and unavailable reads remain visible. High-recipient messages can need an explicit trace ID. |
| Purview unified audit | Mailbox audit is not collected by the live adapter. The audit service's user filter identifies an actor and cannot establish which mailbox the actor accessed. Use an independently authorized export with native mailbox identity for the local evidence package. |
| Current rules and forwarding | `Get-InboxRule` reads selected rule properties for the verified mailbox GUID and requests `IncludeHidden` when available. An unsupported property or hidden-rule limitation is reported. `Get-Mailbox` supplies mailbox forwarding settings. Global Reader and View-Only Organization Management cannot run `Get-InboxRule`. |
| Current delegation | `Get-MailboxPermission` supplies Full Access including trustee, deny and inheritance. `Get-RecipientPermission` supplies Send As. `Get-Mailbox` supplies Send on Behalf. A flattened name or trustee alone cannot establish which mailbox an ACL row belongs to. |
| Entra sign-ins, directory activity and Defender email | Separate sources. Supply appropriately authorized exports for local analysis. The Exchange session provides no evidence of these workloads' coverage. |

[Message trace limits](https://learn.microsoft.com/en-us/powershell/module/exchangepowershell/get-messagetracev2?view=exchange-ps) · [Microsoft mailbox audit scope](https://learn.microsoft.com/en-us/purview/audit-troubleshooting-scenarios#search-for-mailbox-activities-performed-in-a-specific-mailbox-including-shared-mailboxes) · [Inbox rule role limits](https://learn.microsoft.com/en-us/powershell/module/exchangepowershell/get-inboxrule?view=exchange-ps)

A calendar-year request does not extend service retention. BEC shows the unavailable history and requires explicit consent to query only the retained slice. A one-minute moving cutoff guard protects reads near the oldest available boundary, and any omitted interval remains a coverage gap. Use a separately authorized ordinary offline case for older evidence. This run limits trace calls to 100 in any rolling five minutes, with no automatic retry. After an explicit throttle it stops further trace reads and records the remaining ranges as unattempted. Empty results do not establish access, complete coverage or absence of activity.

## Local evidence

Choose a protected local drive with appropriate OS access controls and encryption. BEC writes one export directory per mailbox, its capture receipt, preserved JSON, SHA-256 manifest and reports. The original evidence here is the first local JSON serialization of PowerShell's returned objects. It does not claim to preserve the service's HTTP response bytes. A hash protects evidence relative to the recorded manifest. Retain a separately protected copy for independent custody.

The adapter pins the existing session's `Get-ConnectionInformation`, `Get-Mailbox`, `Get-MessageTraceV2`, `Get-InboxRule`, `Get-MailboxPermission` and `Get-RecipientPermission` commands as applicable. Each trace page must match the direction, account and UTC range before it can be saved. Receipt import checks the saved bytes again. New v3 receipts retain each range's outcome. Trace-only v2 receipts remain supported. Current state is a separate, timestamped observation based on selected native properties. Access and identity gaps remain visible. Workbook links stay inside the file. Original CSVs retain vendor text and should be inspected with a text reader.
